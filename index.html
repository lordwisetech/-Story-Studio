Step-by-step guide
  1. 📂 Import HTML story (Studio tab): choose your story file. Wait for "Ready: N scenes found".
  2. Cartesia key (Voice tab): paste it. With "Remember my key" ticked it is saved and filled in next time. 💾 Save key to text file downloads cartesia-key.txt; 📂 Load key from file reads it back; 🗑 Forget key deletes it from this device.
  3. 🔑 Test API key & load voices: must show a green tick. ▶ Test plays a sample. Narrator / Male / Female choose which voice is used for each role (optional, automatic otherwise).
  4. Video quality (Studio tab): select Full HD for YouTube, Vertical for Reels/TikTok, 720p if your device is slow.
  5. Pace: set before Start. Higher means shorter gaps between scenes. Voice speed never changes.
  6. Auto-sync: ON fits scene animation to each voice line. Toggle before Start.
  7. Record video while playing: untick to only watch the story without making a file.
  8. ▶ Start & Record: first generates all voices, then plays and records. Keep this tab open and visible until conversion finishes.
  9. ⬇ Download MP4: the app records a browser-compatible WebM file, then converts it locally to MP4 (H.264 video + AAC audio). Conversion time depends on your device (a progress percentage is shown). If conversion cannot run on the device, the reason is shown and the original WebM is offered as a fallback.
  10. ↻ Reset: reloads the story so you can change quality or pace and record again.
  11. Prompt tab: type the title and story, then Copy prompt and give it to Claude to make a new story file.
  1. Make the story file: in the Prompt tab type your title and story, copy the prompt, and give it to Claude. You get one HTML file.
  2. Import it in the Studio tab. The app reads its list of scenes (beats).
  3. Voice: every line is generated with Cartesia before playback, so nothing waits or stutters during the video.
  4. Auto-sync: the app measures each voice line and stretches or compresses that scene's animation to fit it.
  5. Record: picture, subtitles and narration are recorded together at your chosen resolution.
  6. Export: the browser recording is converted to MP4 using H.264 and AAC. Conversion runs on your device, not on a remote video server.
Hosting: Use GitHub Pages or another HTTPS host. The first MP4 export downloads the FFmpeg conversion engine (about 31 MB), so keep the page open and connected to the internet during the first conversion. If the file is opened from a local content:// or file:// address, browsers usually block the converter's background worker; you will then get the original WebM instead.
